# 資料來源規則參數規格（第 1 階段）

**Version:** 0.3.79
**Last Updated:** 2026-09-18

日期：2026-09-14。狀態：第 1 階段規格完成；第 2 階段 I01–I07 已實作至自訂 Excel 來源，操作與部署見[第 2 階段說明](source-rules-stage2.md)。第 3 階段預覽與逐來源結果已實作，見[第 3 階段說明](source-rules-stage3.md)；第 4 階段進階匯入已實作，見[第 4 階段說明](source-rules-stage4.md)；查詢／生成接線後續已加入通用自訂來源搜尋、DEG 唯一綁定及勤誠 FZG；其他客戶仍依各自流程。

依據：[現行客戶規則彙總](customer-rules-summary.md)。本文件定義下一階段的範圍、參數、順序、失敗行為及客戶對應。正式機設定與 Excel 實際資料仍以使用者維護值為準。

## 1. 範圍與實作順序

| 階段 | 交付內容 | 本文件用途 |
| --- | --- | --- |
| 1（本次） | 規則參數、執行順序、錯誤行為、客戶對應 | 完成規格，不改正式執行行為 |
| 2 | DEG／自訂 Excel 的選檔、分頁、表頭、欄位、基本轉換與過濾 | 實作本文件標為「2」的參數 |
| 3 | 少量預覽、處理前後比較、逐來源更新結果 | 驗證階段 2 的可操作性 |
| 4 | 對照補值、月份擷取、拆列計算、郵件；查詢與生成規則 | 依真實使用需求逐項抽出 |
| 5 | 舊客戶逐一遷移與部署檢查 | 原始結果與共用規則結果比較 |

第 2 階段先讓新來源可配置，舊客戶繼續走既有處理器。不得因套用共用預設而改變營邦、倫飛、超恩、KOYA、富弘年、勤誠的結果。

## 2. 三類規則的責任

| 類別 | 執行時機 | 內容 | 結果 |
| --- | --- | --- | --- |
| 匯入 | 按「更新資料」及預覽時 | 選檔、分頁、表頭、欄位、轉換、過濾、拆列、計算、補值、去重 | 寫入總表的資料 |
| 查詢 | 載入總表及查詢工單／MO／機種時 | 顯示前補值、別名辨識、關鍵字匹配、MO／數量配對 | 顯示記錄與生成數量 |
| 生成 | 按生成／匯出時 | 型號禁用、序號演算法、區間與數量驗證、輸出欄位 | 序號、箱標與匯出檔 |

同一種「別名」可能分別用於匯入改名及查詢功能欄位辨識，不能只設定其中一處就視為兩者都已生效。KOYA 現在的 SQLite 補值屬載入畫面流程，不能直接宣稱已改成合併程式補值。

## 3. 統一參數慣例

- 列號、欄位置在介面及設定中均由 **1 起算**；讀取器內部才轉成 0 起算。
- 欄名匹配模式為 `exact`（完全一致）、`trim_casefold`（去前後空白及忽略大小寫）、`compact_casefold`（去所有空白及忽略大小寫）。不自動移除其他符號。
- 匯入白名單是要輸出的欄位；表頭提示關鍵字只負責找表頭；必需欄位另行指定。三者不得混用。
- 規則停用與沒有規則均不執行；不預設套用箭頭取值或工單清理。
- 轉換及過濾引用「匯入改名後」欄名；原始欄名保留於預覽及錯誤資訊。
- 文字空值定義為 NA／None 或去前後空白後的空字串；文字 `0` 有值，文字 `nan` 不自動當空值。UUID 的 `0→無` 僅是專用生成規則。
- 保持純文字資料及前導零；日期／數字轉換須明確選用規則。
- 以下「預設」是新規則模式的預設。既有來源未設定新規則時仍採既有流程。

## 4. 匯入參數表

### I01. 來源與選檔（階段 2）

| 參數 | 型別／值 | 預設與行為 |
| --- | --- | --- |
| `path_kind` | `file`／`folder` | 沿用已保存類型 |
| `path` | 非空字串，最多 1000 字 | 沿用已保存路徑 |
| `file_rule` | 字串，最多 300 字 | 空字串；資料夾內檔名包含匹配，保留現有大小寫語意 |
| `file_strategy` | `latest`／`first_valid`／`merge_recent` | 自訂資料夾沿用 `merge_recent`；單檔不受策略影響 |
| `recent_files` | 整數 1–50 | 沿用現值；未指定用 1 |

Excel 檔案類型為 `.xls/.xlsx/.xlsm`，排除 `~$` 與非一般檔案，不遞迴資料夾。依修改時間由新到舊；相同時間以檔名排序，使結果可重現。

- `latest`：只讀最新檔，失敗不偷偷換上一檔。
- `first_valid`：依序嘗試最近 N 檔，取第一個讀取、表頭、必需欄位及處理後有資料的檔案；記錄每次失敗原因。
- `merge_recent`：讀取最近 N 檔並合併；第 2 階段任一選中檔案失敗即視為該來源失敗，不默默產生部分資料。
- 單檔模式直接讀指定檔案，不使用檔名關鍵字篩選。

### I02. 工作表選取（階段 2）

| 參數 | 型別／值 | 預設與行為 |
| --- | --- | --- |
| `sheet_mode` | `first`／`exact`／`contains`／`list` | 舊自訂 `sheet_rule` 空→first；非空→exact |
| `sheet_rule` | 字串，最多 1000 字 | exact／contains 的名稱或關鍵字 |
| `sheet_names` | 非空且不重複的名稱清單 | list 模式使用，不以逗號拆名稱 |
| `sheet_match` | 第 3 節匹配模式 | exact |

first 取工作簿第一分頁；contains 取工作簿順序中的第一張匹配分頁；list 按設定清單順序合併。選不到或 list 缺任一張分頁，視為該檔失敗。全檔有效性仍由 I01 策略決定。

### I03. 表頭（階段 2）

| 參數 | 型別／值 | 預設與行為 |
| --- | --- | --- |
| `header_mode` | `fixed`／`scan` | fixed |
| `header_row` | 整數 1–1000 | 1；fixed 使用 |
| `scan_rows` | 整數 1–1000 | 10；scan 使用 |
| `header_keywords` | 非空文字清單 | scan 必填 |
| `keyword_condition` | `any`／`all` | any |
| `keyword_match` | `cell_exact`／`cell_contains` | cell_exact |
| `header_match` | 第 3 節匹配模式 | trim_casefold |

scan 從第 1 列開始，取第一個命中列。any 只需任一關鍵字在任一格命中；all 必須每個關鍵字都在該列的某格命中。不得跨多格拼字產生假命中。

找不到表頭、固定列超出範圍或表頭全空即失敗，不自動回第 1 列。這是新規則模式的明確行為，舊客戶現有回退行為在遷移前保留。

### I04. 欄位選取、別名與改名（階段 2）

| 參數 | 型別／值 | 預設與行為 |
| --- | --- | --- |
| `column_mode` | `all`／`select` | all |
| `columns` | 依順序排列的欄位定義清單 | select 必填；all 可以只列需改名的欄位 |
| 欄位定義 `name` | 輸出標準欄名 | 非空；來源內不得重複 |
| 欄位定義 `aliases` | 至少一個非空原始欄名候選 | 依設定順序嘗試，不隱含其他別名 |
| 欄位定義 `required` | 布林值 | false；true 且未找到則失敗 |
| `column_match` | 第 3 節匹配模式 | trim_casefold |

select 依 columns 順序輸出，非必需且缺少的欄位省略並警告；all 保留其他原始欄位與順序。沒有可用欄位即失敗。

同一候選匹配到多個欄位、同一原欄被重複選取、改名後撞名或轉換引用無法解析的欄位即失敗，不選「看起來第一個」欄位。空白欄名略過並顯示警告。pandas 可能先加 `.1` 區分重複欄名，預覽須顯示讀取後實際名稱，不能宣稱自動解決所有原始重複表頭。

第4階段新增明確原始欄位置映射（1起算），不猜數字欄名；重複表頭須明確位置區分。

### I05. 欄位文字轉換（階段 2）

`transforms` 為有序規則清單，每筆包含 `field`、`op` 及下列適用參數。所有規則依清單順序執行。

| op | 參數 | 明確行為 |
| --- | --- | --- |
| `trim` | 無 | 去值前後空白 |
| `arrow_last` | 無 | 支援 `->`、`→`、`>`，取最後非空段；無箭頭原值保留 |
| `replace` | `old`、`new` | 字面文字替換；old 不可空，不用 regex |
| `remove_chars` | `chars` | 逐字移除清單中的字元，不等同移除任意字串 |
| `strip_integer_decimal` | 無 | 只移除純數字的全零小數尾碼，如 12345678.0→12345678；12.5 保留 |
| `zero_pad` | `width`，整數 1–100 | 僅純數字左補零；非數字保留；超過寬度不截斷 |

field 必須指定單一標準欄名，不提供全欄默認套用。欄位不存在即失敗，避免規則表面啟用但實際沒執行。

新規則的 arrow_last 與既有後端逐種箭頭分隔的混合符號結果可能不同；階段 5 須以混合箭頭案例比較，不直接改掉舊解析器。

### I06. 列過濾（階段 2）

`filters` 為有序清單，每筆操作指定「排除條件」，多筆規則逐次執行；預設為空清單，不默默刪除原資料。

| op | 參數 | 排除條件 |
| --- | --- | --- |
| `drop_empty_rows` | 無 | 原始已命名欄位經轉換後全空 |
| `drop_empty_field` | `field` | 指定欄空值 |
| `drop_contains` | `fields`（清單或 `all`）、`value`、`case_sensitive` | 任一指定欄包含文字；value 不可空 |
| `keep_digits` | `field`、`length`（整數 1–100） | 指定欄不是恰好該長度的純數字 |

case_sensitive 預設 false。欄不存在即失敗。可用 keep_digits(length=8) 表達 KOYA 八位工單需求。第 2 階段只提供上述已定義條件，不加入任意程式或自訂 regex。

過濾在最終欄位投影前執行，因此可使用不打算輸出的輔助欄位；select 模式仍保留這些欄位供中間計算，不提早丟棄。

### I07. 合併與去重（階段 2）

| 參數 | 型別／值 | 預設與行為 |
| --- | --- | --- |
| `deduplicate` | `none`／`all_columns` | all_columns，沿用既有自訂來源 |

多分頁／多檔縱向合併，缺欄位補空字串，不混入字串 nan。最後欄位投影後再按輸出欄去重；保留第一筆，來源順序即選檔／選頁順序。

若 all 模式在不同檔案中出現同名但對應不同原欄、或改名後跨檔意義衝突，預覽要呈現映射，不能自動推斷兩欄為同一業務欄。

業務鍵去重與 RE 更新由階段 4 處理，第 2 階段不增加通用版本管理。

### I08. 儲存格補值／月份擷取（階段 4）

| 參數 | 定義 |
| --- | --- |
| `cells` | 有序儲存格地址清單，如 A1、B1、A2、B2；取第一個非空值 |
| `target` | 填入所有該分頁資料列的標準欄名 |
| `format` | `raw`（保留文字）／指定日期輸入與月份輸出格式 |
| `overwrite` | `always`／`if_empty` |
| `on_empty` | `blank`／`keep`／`error` |

擷取在逐檔逐頁階段完成，不能先合併再讀單一檔案。KOYA 現況為 raw、always、blank，不应假設 A1:B2 必定是真正日期。

### I09. 對照表補值（階段 4）

| 參數 | 定義 |
| --- | --- |
| `lookup_source` | 指定受支援的 Excel 來源或既有 SQLite 主檔；不允許填任意 SQL |
| `keys` | 有序的「資料欄→對照欄」配對，一個或多個鍵 |
| `fields` | 有序的「對照欄→輸出欄」配對 |
| `match` | `exact`／`family_prefix`，及欄位匹配的文字標準化方式 |
| `duplicate_keys` | `error`／`first`／`last`；無指定新規則採 error |
| `overwrite` | always／if_empty，按輸出欄明確設定 |
| `on_unmatched` | blank／keep／error |
| `on_source_error` | error／blank；新規則採 error，舊客戶按現況遷移 |

family_prefix 使用結尾 `XXXX` 的主檔族群：精確命中優先，再找族群前綴；多個族群匹配時明確報錯，不依資料庫回傳順序選取。

多張對照按清單順序執行，後面的 always 能覆寫前值。來源出錯與單筆未匹配是不同狀況，不能共用一個「找不到就空白」。

### I10. 多工單拆列與計算（階段 4）

參數：工單欄、分隔符清單、數量標記、數量輸出欄、單位用量欄、總用量輸出欄、拆分標記欄、單工單是否也套用數量、同列重複鍵策略。

計算方式明確選擇乘法或按原總數比例分配。比例法必須指定捨入方式與剩餘差額如何分配；現行超恩 Python round 未補差額的行為在遷移前保留。不可把不同數量演算法一概稱作「MAC 計算」。

### I11. 郵件與局部更新（階段 4）

參數：MSG／EML、HTML 本文或附件、取第一張或欄數最多表格、最低欄數、表頭／位置映射、刪除線標記、RE／FW 前綴、主題標準化、原始底稿搜尋、更新鍵與同主題範圍。

先清理與拆列，再按新舊郵件套用局部更新，之後才做對照補值。新規則建議限制同主題更新；現行超恩跨底稿雙鍵替換須作相容性案例，不在階段 2 修改。

### I12. 特殊版面（階段 4，實際需要時）

赫星的標籤列轉記錄需指定標籤所在欄、資料開始欄、Model 多值列、其他欄第一非空值及輸出欄。先保留赫星專用解析器，不為 DEG 預先開發通用轉置功能。

## 5. 查詢與生成參數（階段 4）

| 編號 | 功能 | 參數與行為 |
| --- | --- | --- |
| Q01 | 功能欄位別名 | 工單／MO／型號／數量等功能代碼→標準欄及候選；與匯入改名分開 |
| Q02 | 查詢匹配 | 目標欄、token 分隔符、精確／包含優先序、是否搜尋整列；赫星另有前 6 字元 |
| Q03 | MO／數量配對 | 查詢欄、數量欄、`/` 分隔符、按命中位置取數量；未配對的回退方式、正整數驗證 |
| Q04 | 載入後補值 | 如 KOYA SQLite 型號及月份主檔；沿用 I09 的匹配／覆寫語意，但明確標示執行在畫面載入 |
| G01 | 型號限制 | 型號欄、精確清單／前綴、提示文字、是否禁止；前後端使用同一判斷來源 |
| G02 | 序號演算法 | 選現有受支援營邦／倫飛／超恩區間／Cubepilot／DEG 規格及其必要參數，不輸入任意程式 |
| G03 | 數量與區間驗證 | 正整數、流水號上限、MAC／SN／UUID 筆數、起訖與格式；保持現有信任邊界驗證 |
| G04 | 匯出 | 分頁名稱、欄位與順序、單筆箱標／多筆標籤、日期來源；沿用既有輸出策略 |

第 2 階段不因新來源能匯入就自動建立查詢客戶、接上 DEG 生成或允許序號演算法配置。

## 6. 新規則模式的執行順序

1. 驗證設定，確認操作與參數受支援。
2. 選檔、排序並按檔案策略讀取。
3. 每檔選頁、辨識表頭、建立欄名及別名映射，保留來源資訊。
4. 逐頁擷取儲存格補值（階段 4）；保留原始欄供預覽與後續過濾。
5. 按 transforms 清單順序轉換；按 filters 清單順序過濾。
6. 拆列及計算（階段 4）；按配置的驗證排除或拒絕無效記錄。
7. 依工作表與檔案順序合併；郵件版本更新另採明確舊→新順序（階段 4）。
8. 按對照清單順序補值（階段 4）。
9. 最終欄位選取與排序，再執行去重。
10. 檢查是否有有效輸出；更新來源結果，成功資料進入總表原子寫入。

各客戶現有順序可能不同；遷移時需由等價結果驗證決定是否可改走上述流程。

## 7. 錯誤、警告與更新狀態

| 狀況 | 行為 | 回報內容 |
| --- | --- | --- |
| 參數型別、範圍、操作不符 | 保存拒絕；不覆寫已保存設定 | 欄位或規則索引與原因 |
| 路徑、權限、檔案、分頁讀取失敗 | 預覽／更新顯示來源失敗；first_valid 可試下一檔 | 來源、檔案、分頁及階段 |
| 表頭未命中、必需欄缺少、映射歧義 | 當檔失敗；按策略決定是否回溯 | 掃描範圍、缺欄與實際欄名 |
| 非必需選取欄不存在 | 警告，省略該欄 | 缺少欄名及候選 |
| 轉換／過濾欄位不存在 | 來源失敗 | 規則索引、操作、欄名 |
| 過濾後無資料 | 沒有有效輸出，不以空分頁覆蓋舊分頁 | 輸入／過濾／輸出筆數 |
| 部分來源失敗，但其他來源成功 | 保持既有總表容錯；逐來源區分結果 | updated／retained／skipped／failed |
| 所有來源都沒有本次成功資料 | 任務失敗，保留原檔 | 各來源原因 |
| 總表寫入／替換失敗 | 任務失敗，保留原檔 | 寫入階段原因 |

- `updated`：本次成功輸出該來源。
- `retained`：本次失敗，但沿用舊同名分頁；仍顯示本次失敗原因。
- `skipped`：來源已執行但沒有可寫入資料，且無舊分頁可沿用。
- `failed`：讀取／規則／寫入出錯的原因分類；來源最終結果可同時標為 retained 或 skipped。

保存只驗證設定結構。路徑是否可讀、表頭及規則是否符合資料由預覽／執行驗證；不要把「保存成功」當作「規則已驗證」。

## 9. 第 2 階段設定保存方式

設計採沿用 shipment_source_config，新增一個規則 JSON 欄位；不建立新的規則資料庫、不加入通用規則框架。只有第2階段需要的參數才落地。

- 沒有新規則設定：使用來源目前的讀取／處理方式。
- 明確保存新規則：以 `version: 1` 與第2階段參數執行；未知版本或操作拒絕，不當作停用。
- 原有 path/sheet_rule/file_rule/recent_files 繼續作為既有欄位；規則 JSON 不重複保存同一參數。
- 路由、schema、service、合併程式、前端須同批部署。版本不支援時明確回報，避免保存後更新程式忽略規則。
- 舊客戶不自動切換到新規則模式；遷移由階段5逐一驗證。

## 10. 後續最小驗證案例

| 案例 | 預期結果 |
| --- | --- |
| DEG以原設定、無轉換規則執行 | 與現況欄位及資料一致，不猜測欄名或套用八位工單限制 |
| 表頭在第3列，設定fixed(3) | 第1/2列不成資料；正確取得第3列欄名 |
| 設定多頁、其中一頁不存在 | 明確失敗；first_valid可回溯下一檔；不宣稱全部已匯入 |
| 同名輸出欄或別名匹配歧義 | 保存或執行拒絕，不靜默覆寫 |
| 過濾需要未輸出的備註欄 | 先過濾後投影，備註不寫入總表 |
| 工單12345678.0、12.5、00123456 | 只將第一值改成12345678，其他值不因清理而截斷或丟前導零 |
| zero_pad(8)接keep_digits(8) | 短純數字補零；過長或非數字由過濾排除，不截斷 |
| 最新檔失敗、前一檔有效 | latest失敗；first_valid使用前一檔；merge_recent失敗且保留舊分頁 |
| 一個來源成功、另一個失敗有舊資料 | 各自顯示updated與retained，沿用來源同時顯示失敗原因 |
| 不支援的新規則／版本 | 保存或執行明確拒絕，不悄悄忽略 |

舊客戶遷移另用現行結果作對照，至少覆寫營邦缺頁、倫飛型號限制、超恩RE雙鍵替換及拆列MAC差額、KOYA SQLite覆寫PO、富弘年日期形狀與勤誠全部欄位。
